# Release scenarios

Local files and fixture HTTP servers; no model or vendor calls.

- Named targets must be each executable's; unnamed targets are all of theirs.
- Each runner release has its directory; the manifest names the last complete release.
- Backend and manager releases record their version and are immutable.
- Development releases carry selected targets and declared operations.
- Command releases carry resource archives, reuse their cache and reject corruption.
- Browser pins record every official archive and its executable; reject wrong metadata, unofficial URLs and missing entries.
- Image packaging embeds verified inputs and publishes a manager-readable manifest.
- Corrupt artifacts and unfinished dpkg installations publish no image.
- Fork comparison names changes and counts omitted upstream files, against a fixture module.
- Development backend signs in the seeded account, answers hello with Echo: hello, and stops every process and removes its data on interrupt (pending b-backend).

Rust-only SDK and sparse crates.io layout tests do not apply to Go. The five
Rust architecture tests are accounted for individually in the handoff report.

The implemented scenarios use `artifactstest` for HTTP and ZIP fixtures and
x/mod's signed in-memory checksum server for module verification. Image tests
substitute the Linux GNU tar process with a local tar writer on this Mac; Linux
ownership, ACL and extended-attribute acceptance remains a platform check.
The normal suite takes about 1.1 seconds; the race suite about 4.3 seconds.
`TestDevSeededAccountEchoAndShutdown` explicitly skips until b-backend programs
are available; it will drive dev in process, including its own builds, without
programtest. Echo HTTP streaming and Unix process shutdown are exercised
independently in the default suite. The dev scenario builds the backend, manager
and other programs once and then uses the shared Go build cache.

`uv.json` is generated by `go generate` from
`cloud-guest-image/rootfs/uv.json`, the authoritative pin. The copy is embedded
so a cross-built image assembler needs no source checkout on its Linux builder.
No Rust fixture generator was needed: the reference scenarios construct their
fixtures in memory, and the Go tests do the same.

`TestEmbeddedUVPinMatchesSource` fails if the generated copy is stale and names
the regeneration command. `TestDevConfigNamesRelativeReleasesInLocalStore` reads
the written configuration through the backend decoder and checks the relative
release directories and local store.

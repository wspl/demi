utility runs in a test), the plan's Gate B criteria, and the utility catalog:
/home/user/demi-base/crates/runner/src/shell/utilities.rs (NAMES).
References here: GNU coreutils 9.4, grep 3.11, sed 4.9, findutils 4.9,
diffutils 3.10, /usr/bin/rg, /usr/bin/jq, run as black boxes.

Deliver:
1. internal/testing/gnucorpus: a Go harness. A case = name, argv, stdin, a
   file tree to create first, and the expected stdout (bytes), exit code,
   whether stderr is non-empty, and the resulting file tree when the utility
   writes files. `gnucorpus.Check(t, utilityName, utility, cases)` runs each
   case through toolctxtest in a fresh temp dir and compares. Environment for
   every case: LC_ALL=C, TZ=UTC, a fixed HOME inside the temp dir.
2. A recorder (a Go test helper or a program under internal/testing/gnucorpus/
   record, run explicitly, never in normal tests) that runs the GNU reference
   for every case in the same setup and writes the expectations to
   testdata/gnu/<utility>/cases.json. Commit the recorded files.
3. Corpora for all 41 utilities, in this order (the text family first; T1a
   starts from it): cat head tail wc tee sort uniq cut tr | grep rg find xargs |
   sed jq | ls cp mv rm mkdir rmdir touch stat du df chmod chown realpath mktemp |
   basename dirname env seq date sleep paste nl tac od | diff cmp.
   Per utility: a core set (every option the old tests in /home/user/demi-base
   use — grep packages/ and crates/ tests for invocations — plus the options
   coding agents commonly use) and an extended set (the rest of the documented
   options worth supporting). Mark each case core or extended. Outputs that
   depend on time, user names or inode numbers are normalized or avoided.
4. A short testdata/gnu/README.md: format, how to re-record, and the list of
   core options per utility (the orchestrator approves it).
Owned paths: internal/testing/gnucorpus/**, testdata/gnu/**.
Checks: scripts/go-check.sh; the recorder reproduces the committed files.
